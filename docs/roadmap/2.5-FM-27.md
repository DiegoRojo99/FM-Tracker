# 2.5 FM27 Integration Roadmap

**Status:** In Progress
**Last Updated:** 2026-11-06
**Target Completion:** Q1 2027

## Overview

This roadmap defines the strategy for integrating Football Manager 2027 (FM27) game version into FM-Tracker. FM27 represents the 2026/27 season in Football Manager and includes updated team rosters, competitions, and leagues.

The app already supports multi-game versions (FM24, FM25, FM26) with a progressive data pipeline for competitions, teams, and gender-aware league filtering. FM27 integration will follow the established patterns while adding the latest season data and validating against evolving game structures.

### 1.3 Competition & Team Data Import

#### Agreed Scope (2026-11-06)

- Retain FM26 playable domestic-league coverage for men and women.
- Add only these two leagues to that coverage:
  - Men's Roshn Saudi League / Saudi Pro League.
  - Women's Arkema Première Ligue (French top division).
- Import team records and league-season membership only, using approved domestic-league API mappings.
- Player rosters, squads, player records, and transfers are out of scope.
- Do not fetch teams from cups, continental competitions, or qualifying rounds.
- Cup and continental competition metadata is outside this subphase; existing trophy support is preserved.
- Do not equate every currently active database group with an approved FM26 league: reconcile mappings, duplicates, and gender classification first.
- Discuss and approve scope before each subsequent subphase. No database seeding until the read-only inventory is reviewed and execution is explicitly approved.

#### Import After Approval

Importer preparation is implemented. `npm run teams:fm27:dry-run` fetches API data and compares it with the database selected by `NODE_ENV`, without database or Algolia writes. Explicit `--dry-run` overrides inherited execute settings; passing both command-line modes is rejected.

- FM27 mode selects app season `2026/2027`, requests J1 API season `2027`, and requests API season `2026` for the other validated leagues.
- Only domestic-league mappings are processed, deduplicated by API ID. Approved additions/mapping repairs are included; unavailable or excluded sources and conflicting new memberships are omitted.
- Metadata, country activation, group/link changes, teams, and missing memberships are compared before execution. Existing historical memberships are not removed.
- API requests are paced to avoid the observed per-minute rate limit; API errors stop the run explicitly.

## Technical Considerations

### Database Schema
- Reuse existing `Save`, `Competition`, `Team`, `Trophy`, `Season` models
- No new models required for FM27 support
- Ensure `gameId` field is consistently used as discriminator

### API Integration
- Validate API schema matches FM26 (no breaking changes expected)
- Implement retry logic for data import failures
- Cache API responses to avoid rate limiting

### Data Migration Path
- Zero-downtime deployment (add FM27 as new option, don't modify existing data)
- Backward-compatible database queries
- Gradual data import (can import competitions in batches)

### Performance
- FM27 data addition should not impact existing FM26 query performance
- Monitor N+1 queries when fetching saves with games
- Consider data partitioning if dataset grows significantly
