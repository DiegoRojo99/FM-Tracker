# 1.1 Data Model Audit - Indexes and Unique Constraints

Date: 2026-08-03
Scope: Prisma schema plus current Prisma query patterns in API and DB modules.

## Outcome

- Existing unique constraints are generally solid for data integrity.
- Several high-value composite indexes are missing for common filter + sort query paths.
- No destructive change is required for this step; this is an audit and implementation recommendation set.

## Integrity Review (Unique Constraints)

No critical integrity gaps found in core entities:
- `User.email` unique exists.
- `FriendRequest(requesterId, receiverId)` unique exists.
- `Friendship(user1Id, user2Id)` unique exists.
- `Season(saveId, teamId, season)` unique exists.
- `Trophy(competitionGroupId, season, saveId)` unique exists.
- `CareerChallenge(userId, challengeId, saveId)` unique exists.
- Junction tables keep uniqueness constraints where expected.

Notes:
- Some unique fields already imply indexes (for example `User.email`), so additional single-field indexes may be redundant.

## Query-Driven Index Gaps

### High Priority

1. `FriendRequest` inbox/outbox queries
- Observed pattern:
  - where `receiverId = ?` (+ optional `status`) ordered by `requestedAt DESC`
  - where `requesterId = ?` (+ optional `status`) ordered by `requestedAt DESC`
- Recommended:
  - `@@index([receiverId, status, requestedAt])`
  - `@@index([requesterId, status, requestedAt])`

2. `Friendship` list queries
- Observed pattern:
  - where `user1Id = ? OR user2Id = ?` ordered by `createdAt DESC`
- Recommended:
  - `@@index([user1Id, createdAt])`
  - `@@index([user2Id, createdAt])`

3. `CareerChallenge` history queries
- Observed pattern:
  - where `challengeId = ? AND userId = ?` ordered by `startedAt DESC`
- Recommended:
  - `@@index([userId, challengeId, startedAt])`

4. `Trophy` per-save list queries
- Observed pattern:
  - where `saveId = ?` ordered by `season DESC`
- Recommended:
  - `@@index([saveId, season])`

### Medium Priority

5. `TeamSeason` league roster queries
- Observed pattern:
  - nested relation filter by `apiCompetitionId` and optional `season`
- Recommended:
  - `@@index([apiCompetitionId, season])`

6. `PromotionRelegation` lookup queries
- Observed pattern:
  - where `fromGroupId = ? AND type = 'promotion' | 'relegation'`
- Recommended:
  - `@@index([fromGroupId, type])`

7. `Save` participant/game scans
- Observed pattern:
  - where `userId IN (...)`, sometimes grouped/distinct by `gameId`
- Recommended:
  - `@@index([userId, gameId])`

## Safety Notes

- Create indexes in a dedicated migration with no data-destructive operations.
- Run migration first in local/staging, then production.
- Verify production backups before applying migration.
- Do not use reset-style commands in production.
